# Anonymizer Benchmark

Harness for evaluating de-identification methods on a dataset generated by our
pipeline. It is scoped to the **text-replacement** setting: an anonymizer returns
the full document with every PII entity replaced by a `[REDACTED]` marker, and
the bundled [`scoring`](scoring/) package (text mode) aligns that output back to
character offsets before scoring it against the by-construction gold spans.

Six methods are currently registered:

- `rule_based` — a deterministic REGEX-GAZ baseline (regular expressions +
  external gazetteers + document-structure cues). Its name/place lexica are
  drawn from the [Faker](https://faker.readthedocs.io) German locales, i.e. from
  a public source independent of the generator's pools, so there is **no
  privileged tuning**. It needs no API access or cache. See
  [`rule_based_config.yaml`](rule_based_config.yaml).
- `presidio` — [Microsoft Presidio](https://microsoft.github.io/presidio/)'s
  `AnalyzerEngine` with a German spaCy pipeline (`de_core_news_lg`). Named
  entities come from spaCy NER; dates, phone numbers, e-mail, URLs, etc. come
  from Presidio's language-agnostic pattern recognisers. Used out of the box (no
  custom recognisers), it also needs no API access. See
  [`presidio_config.yaml`](presidio_config.yaml).
- `flair` — the off-the-shelf
  [`flair/ner-german-large`](https://huggingface.co/flair/ner-german-large) NER
  model as the entity backbone, wrapped in Presidio so it reuses the same
  pattern recognisers as the `presidio` method. It differs from `presidio` only
  in the NER engine (Flair instead of spaCy), making the two a controlled
  comparison. First run downloads ~2 GB of weights. See
  [`flair_config.yaml`](flair_config.yaml).
- `openmed` — an off-the-shelf German clinical PII detector,
  [`OpenMed/OpenMed-PII-German-ClinicalE5-Base-109M-v1`](https://huggingface.co/OpenMed/OpenMed-PII-German-ClinicalE5-Base-109M-v1),
  a token-classification model trained specifically for de-identification (54
  PII entity types). It runs standalone (no Presidio pattern layer); because
  scoring is detection-only, its label taxonomy is immaterial. The model is
  trained on short, templated PII sentences and loses recall on whole clinical
  letters, so documents are split into line/sentence segments before
  classification and the predictions are mapped back to global offsets. First
  run downloads the model weights. See [`openmed_config.yaml`](openmed_config.yaml).
- `gemini` — an LLM de-identifier (see `example_config.yaml`).
- `lmstudio` — open-source LLMs served locally by
  [LM Studio](https://lmstudio.ai) through its OpenAI-compatible server. This is
  a drop-in backend swap for `gemini`: it reuses the **exact same** prompt,
  structured-output schema, mode-scoped cache key, and retry/back-off policy, so
  the local models are directly comparable to the hosted baseline. One method,
  parameterised by `lmstudio_model` (the model key LM Studio serves — confirm
  with `curl http://localhost:1234/v1/models`). Three configs are provided:
  [`lmstudio_sauerkraut_config.yaml`](lmstudio_sauerkraut_config.yaml)
  (Llama 3.1 SauerkrautLM 8B Instruct, Q2_K),
  [`lmstudio_qwen3_config.yaml`](lmstudio_qwen3_config.yaml) (Qwen3 35B A3B,
  Q4_K_M), and [`lmstudio_gemma_config.yaml`](lmstudio_gemma_config.yaml)
  (Gemma 4 E2B). Load the corresponding model in LM Studio and start its local
  server before running.

Add more methods by implementing an `Anonymizer` (see `anonymizers/base.py`) and
registering it in `anonymizers/__init__.py`.

## Usage

```bash
python -m experiments.benchmark --config experiments/benchmark/example_config.yaml
```

Options:

- `--output DIR` — override `output_dir` from the config.
- `--limit N` — score only the first `N` documents (smoke test; the report is
  computed against exactly that subset).
- `--log-level {DEBUG,INFO,WARNING,ERROR}`.

## Output

Artifacts are written to `<output_dir>/<anonymizer.name>/`:

- `deid_texts.jsonl` — one `{"doc_id", "text"}` record per document (the
  PHI-replaced text).
- `report.json` — the full evaluation report (detection P/R/F1, risk-weighted
  recall, over-anonymization/negatives, faithfulness, boundary quality).
- `gold_subset.jsonl` — only when `--limit`/`limit` is set; the exact gold
  documents scored.

A human-readable summary is also printed to the console.

## How it works

1. **Predict** — the anonymizer runs over every document (with configurable
   concurrency). Responses are cached in a SQLite database, so reruns are free
   and an interrupted batch resumes instantly. Per-document failures fall back to
   the original text (counted as misses) rather than dropping the document.
2. **Evaluate** — `deid_texts.jsonl` is handed to
   `experiments.benchmark.scoring.evaluate` in text mode.

## Configuration

See [`example_config.yaml`](example_config.yaml). All paths are resolved relative
to the config file. Key fields:

- `dataset_path` — gold JSONL (`doc_id` / `text` / `spans`).
- `anonymizer` — method `name`, `model`, cache path, `temperature`, retry policy,
  and `workers`.
- `evaluation` — `matching` (`strict` | `lenient` | `token`) and `iou_threshold`.
